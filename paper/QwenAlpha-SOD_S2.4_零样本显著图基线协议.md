# S2.4 零样本显著图基线协议（草案，待审）

**状态：** Draft v2 — 提示词与选择规则已按评审意见修订（P1–P4、亮度定胜负）；执行需另行确认

**目的：** 测量 Qwen-Image-2.1 在**不做任何处理**的情况下，仅凭原图生成灰度显著图的能力，作为两条技术路径的共同基线。

**性质：** 纯测量。不训练、不微调、不改权重、不做后处理、不设通过/不通过门槛。

---

## 1. 冻结项（跑之前必须确认，跑之后不得更改）

| 项 | 冻结值 |
|---|---|
| 输入 | 仅原图 RGB；不提供 GT、mask、类别、数据集名、文件名 |
| 输出 | 模型生成的 RGB 图，按 §4 固定规则转灰度 |
| 权重 | S2.1 固化的官方快照（VAE 哈希 `a07a1b7c…`，逐文件 SHA-256 已记录） |
| 训练 | 无。零优化步、零 LoRA、零 adapter |
| 后处理 | 无。不做对比度拉伸、gamma、形态学、阈值调参、多结果择优 |
| 模型 | `Qwen-Image-2.1`，bf16，`enable_model_cpu_offload`，单卡物理 GPU 1 |
| 采样 | 1024×1024，`num_inference_steps=40`，seed = 20261029 + index |
| 提示词 | §3 四候选（P1–P4）中选定一个后冻结，全 100 张同一模板 |
| 评测集 | 100 张 `vae_audit`（EORSSD 38 / ORSI-4199 51 / ORSSD 11，全部 train 划分） |

**明确禁止：** 因某张结果差就换提示词；因某类样本差就换模板；用审计集调参后仍把该数当零样本基线。

## 2. 两条读数与一个参照

| 项 | 说明 | 用途 |
|---|---|---|
| 亮度读数 | 原图 + 指令 → 输出 RGB → BT.601 亮度 | **基线主数，模板选择的唯一依据** |
| alpha 读数 | 同一张输出的第 4 通道 | 并列诊断，**不参与模板选择** |
| 上限参照 | S2.3 的 VAE 往返（oracle 输入，Sα 0.9643 / MAE 0.0052） | 判断零样本离表示上限还有多远 |

两条读数共用一次生成：模型输出的 RGBA PNG 同时提供亮度与 alpha，不额外跑 GPU。

论文的最终产物是灰度图，因此**基线一律以亮度定义**；alpha 只作为"原生通道是否更可用"的旁证单独报告，是否升格为方法的一部分，等两组数出来再定。

## 3. 提示词候选与选择规则

四个候选（英文；中文模板在 Qwen3-VL 上的行为未经验证，不纳入），分别对应模型可能理解的四种表达方式：

| 候选 | 措辞 | 设计依据 |
|---|---|---|
| **P1 原生透明** | `This is an RGBA image with transparency. The salient object of this photo. The image has alpha channel and the background is transparent.` | 模型卡原文句式，官方推荐用法 |
| **P2 去背景编辑** | `Remove the background and keep only the salient object, on a pure black background.` | 图像编辑模型最自然的操作形态 |
| **P3 显式术语** | `Produce a grayscale saliency map of this image: the salient object in white, the background in black.` | 直接对齐任务术语 |
| **P4 极简高亮** | `Highlight the salient object in this photo.` | 经典提示词写法，最低信息量基线 |

四条构成对照：**原生用法 / 编辑指令 / 任务术语 / 极简**。相较草案初版，去掉了"Convert this photo into a grayscale saliency map"这类把风格转换与目标提取混在一句的写法，也补上了官方透明背景句式。

**选择流程（必须先做，且不得在审计集上做）：**

1. 探针集：从 `manifests/all_samples.csv` 取 `dataset=EORSSD`、`official_split=train`，排除全部 `vae_audit` 与 `overfit_*` 样本，按 `sample_id` 升序，等距抽 **10 张**，ID 列表写入报告。
2. 四个模板 × 10 张 = **40 次生成**（约 40 分钟）。
3. **以亮度口径的 Sα 均值最高者为胜**；并列时取 MAE 更低者。alpha 口径同步记录，但**不参与选择**。
4. **四个模板的分数全部写入报告**（亮度与 alpha 两列都给），不得只报胜者——选择过程本身是证据。
5. 冻结胜者，再跑 100 张审计集，**只跑一次**。

**中止条件：** 若四个模板在探针集上的亮度口径 Sα 均值都 < 0.30，说明"零样本直接出显著图"这一前提不成立。此时不跑 100 张，改为提交"前提不成立"的失败报告，并讨论改表示（例如两阶段：先让模型输出文字描述/框，再生成掩码）。

**为什么不用 alpha 选模板：** P1 的输出很可能只有 alpha 有意义、RGB 内容不保证；若用 alpha 选，会系统性偏向 P1，而论文产物是灰度图。用亮度选、alpha 并列报告，才能回答"在不额外假设通道的前提下，零样本能做到什么"。

---

## 4. 灰度与 alpha 的转换规则（冻结）

- 模型输出 → 保留 RGBA 原始 PNG（证据）。
- **灰度**：`Y = 0.299·R + 0.587·G + 0.114·B`（BT.601），归一化到 [0,1]，不做任何拉伸。
- **alpha**：直接取 A/255。
- 二值化只用于 Boundary-F 与 IoU 的 0.5 阈值，不用于生成灰度图。
- 若输出不是黑底（例如整幅被重绘、有彩色残留、全白/全黑），**如实记录，不修改规则**；这类样本计入失败统计。

---

## 5. 评测

**主口径**：把预测图 resize 到 GT 原尺寸（双线性），GT 保持原始二值。

**辅口径**：与 S2.3 完全一致的 352² 目标面积口径，用于直接比较"零样本 vs 表示上限"。

指标复用 `scripts/s2_3_vae_audit.py` 中的实现（同一份代码、同一套定义，避免口径漂移）：

- Sα（Fan 等人 S-measure，α=0.5，四象限加权，钳制 [0,1]）
- Fmax（β²=0.3，256 阈值）
- MAE
- Boundary-F（±2 px 容忍）
- IoU（0.5 阈值，辅助）

另按数据集、按类别（small / thin / multi / low_contrast / shadow / holes / empty / large）分组报告均值与最差 10 张。

## 8. 结果如何解读（跑之前先写死，避免事后解释）

基线数出来后，按下列判据选路径，**不得在看到数字后修改判据**：

| 零样本 Sα（352 口径） | 含义 | 建议路径 |
|---|---|---|
| ≥ 0.85 | 已接近传统方法量级 | 路径 2（弱/无监督提升）性价比最高 |
| 0.70 – 0.85 | 有明显差距但基础可用 | 两条都可行：路径 1 更稳，路径 2 故事更强 |
| 0.55 – 0.70 | 差距明显 | 路径 1（全监督）为主，路径 2 仅作消融 |
| < 0.55 | 前提存疑 | 先解决表示/提示，不进入训练 |

同时报告"零样本 Sα / 0.9643"这一比值，作为"离表示上限还有多少空间"的量化说明。

## 9. 已知风险

1. **模型可能不理解"显著图"**，输出重绘照片或带风格的图——这正是要测的，如实记录为能力边界。
2. **提示词选择偏差**：探针只有 10 张，方差可能大；因此三模板分数全报，且探针集与审计集严格不相交。
3. **分辨率错配**：模型在 1024 生成，GT 是原尺寸，resize 会引入模糊；辅口径（352²）用于对照。
4. **"灰度"是否等价于"显著性"**：模型可能输出黑底白字的其他内容；靠 GT 指标自动暴露，不靠人工挑选。
5. **P1 的通道错配**：官方透明背景句式下，RGB 内容可能不保证有意义，亮度读数会低估它；这正是要用 alpha 列并列报告的原因。若最终 P1 亮度很差但 alpha 很好，属于"需要单独立项"的发现，不得直接替换成 alpha 结果充当基线。
